# How to run the beauty ad pipeline (README)

> **17-Nov: QC stages removed.** Skip the frame gate (step 5), `check_actions.py`, `validate_concepts.py`, `product_text.py check` and the `--dry` review round. `generate_clips.py --confirmed` no longer runs `check_actions.py` (pass `--check` to turn it back on). One take per image and per clip.

This zip holds only the pipeline: scripts, rules and one worked example (`example_run_ID_4/`, text and JSON files only, no images or videos). Start here, then read `SKILL.md` (the short general skill), `CATEGORY_RULES.md` (what to do per product category), `PROMPT_LOCKS.md` (locks 1-20), `REALISM_RULES.md` and `PIPELINE_CONCEPT_LAB.md`.

One run = one sheet row (persona + avatar + hook + 5 Flipkart products) -> one reel of at most 30 s (end slate included), portrait 1080x1920, music only.

## 0. Setup (once)
- Python 3 with `Pillow` (`pip3 install Pillow`), `ffmpeg` at `/opt/homebrew/bin/ffmpeg`.
- `.env` next to `omni.py` holds the only two tokens the pipeline uses: `OMNI_MCP_URL`, `OMNI_TOKEN`.
- Not in this zip, you need them on the machine:
  - brand assets in `<pipeline folder>/assets/brand_beauty` (`Flipkart_End_Slate.mp4`, `logo_overlay.png`, `fonts/Poppins-ExtraBold.ttf`, `fonts/Inter-Bold.ttf`)
  - music packs in `<pipeline folder>/assets/music/rhythm_bgm_approved (Rhythm sheet: ONLY these approved RHY_BGM tracks, bgm_pack = rhythm_bgm_approved)`
  - the Omni folder `Flipkart_Fashion-Rhythm_AI_Profiles` (must exist; every generation is filed there)
- Images are generated with the Omni connector tool `generate_nano_banana_image` (model `gemini-3.1-flash-image`, 1K, 9:16) from Claude, not by a script here. Videos are generated by `generate_clips.py` (model `gemini-omni-1.2-flash`, 360p only, first frame only). Never generate above 360p and never generate without the user's approval.

## 1. The run folder
`Diwali_Lips_Batch_<date>/ID_<row>/` with `01_product_manifest.md`, `02_creative_brief.md`, `03_character_and_environment_bible.md` (includes `skin_tone` and `nails` from the avatar), `04_storyboard.md`, `04_actions/*.json` (one per clip), `05_product_accuracy.md`, `08_run_log.md`, `product_text.json`, `clip_frames.json`, `assets/` (anchor, plates, product_refs, keyframes, video_clips, bgm), `exports/`.

## 2. Steps for each run
1. **Concept card** (see `PIPELINE_CONCEPT_LAB.md`): unique room setting (a real lived-in HOME, never a kitchen), archetype, light, hook device, palette, wardrobe, `bgm` (an UPBEAT track no earlier run used (upbeat packs only), from `<pipeline folder>/assets/music/rhythm_bgm_approved (Rhythm sheet: ONLY these approved RHY_BGM tracks, bgm_pack = rhythm_bgm_approved)`, with `bgm_pack` in the card), `skin_tone`, `application_count: 1`, `apply_product`, `show_devices` (all different). Check it: `python3 validate_concepts.py concepts_batch.json` (compares with `concept_registry.json`), then add it to the registry.
2. **Products**: read the Flipkart pages and photos (curl with a browser User-Agent), write `01_product_manifest.md`. Verify price/discount claims from the listings; drop unverified claims from the on-screen header. No prices on screen.
3. **Product text**: write `product_text.json` (brand, name, variant, exact front-of-pack words read from the photo, colour, pack) and check `python3 product_text.py <run> check`. `python3 product_text.py <run>` prints the PRODUCT TEXT block to paste into every image prompt that shows a product.
4. **Avatar and room plate**: download the avatar (Drive public `uc?export=download&id=`), build the identity sheet and a head-and-shoulders face anchor (no products), generate ONE empty-room plate (no person, no products) with the surface the creator will sit at. Upload references to Omni.
5. **Keyframes** (images only, first frames only, one take each; never a last frame): hook (creator face 1 of 2), the one application (creator face 2 of 2, product already open, nothing applied yet), tight hands-only product close-ups (each held a different natural way), a b-roll master. Every prompt carries the locks in `PROMPT_LOCKS.md` and the PRODUCT TEXT block. Gate each frame before any clip: every product exactly once, exactly one person and two hands, hands match the avatar's skin tone, products on the same surface the creator uses, hands enter from the bottom or sides, true product sizes, nothing floats. Never pass a flawed frame as a reference.
5b. **Hands clause**: for every close-up paste the output of `python3 hands_prompt.py <hold> [right|left]` into the frame prompt and store it as `hands_clause` in the clip's action JSON (check_actions.py requires it for show clips). Trace each forearm to a frame edge at the gate (lock 18). Approve every frame BEFORE any clip is generated.
6. **Action files**: one JSON per clip in `04_actions/` (see `action_input.example.json`) with `beat_type` (show/apply), unique `show_device`, `opens`, camera line per step. Run `python3 check_actions.py <run>`: it must print OK (also checks `product_text.json`).
7. **Clips**: write `clip_frames.json` (clip name -> first-frame asset id), then
   `python3 generate_clips.py <run> --dry` (prints prompts and total seconds, costs nothing), and after the user approves
   `python3 generate_clips.py <run> --confirmed` (add `--stagger 15` if the Omni service returns 502s). All clips are submitted together, then it waits for all and downloads the mp4s. One take each. Existing mp4s are skipped.
8. **Assemble**: copy `assemble_template.py` into the run folder as `assemble.py`, edit CLIPS/CHIPS/header/OUT/music, run it: hard cuts only, header on the whole film, product chips, "Shop Now on Flipkart" only in the last 2 s, end slate, music with fades. Output `exports/*_master.mp4`; copy it to the Desktop output folder.
9. Update `08_run_log.md` (images and clips generated, assets, retries, open issues).

## 3. Rules in one place
- `PROMPT_LOCKS.md`: locks 1-15 (proportions, no duplicates, natural gestures, zoom, framing, room, realism, eye stability and opening motion, nothing applied in the first frame, two hands only, product text, same surface, hands from below, hold logic, skin-tone match, the application must really happen). `omni.py` appends the clip-level locks to every clip prompt automatically; image prompts must include them by hand.
- `PIPELINE_CONCEPT_LAB.md`: concept lab, one application per video, creator budget (face in at most 2 clips, the rest hands-only close-ups), home settings only, different BGM every run, open-state references, canonical plates, all clips submitted at once.
- `Script_Storyboard_Rules_from_Reels_2026-11-04.md`: script and storyboard rules and the 30 s cap.
- Do not use the opencv label overlay.
- `REALISM_RULES.md`: the realism note (casual phone video, ordinary neat middle-class home, imperfections). `CATEGORY_RULES.md`: per-category guidance (makeup, fragrance, apparel, footwear, decor, furnishing, wearables, pets and others). `SKILL.md`: one-page general skill with the stages and commands.
- `example_run_ID_4/`: the run folder files of ID_4 (Sunita, lipstick, realism version): manifest, brief, bible, storyboard, `product_text.json`, `clip_frames.json`, `concept_card.json`, `04_actions/*.json`, the per-run `assemble.py` and the run log. Copy its shape for a new run.

## 4. Scripts
| File | What it does |
|---|---|
| `omni.py` | Omni MCP client (`tool`, `action_prompt` with all locks); reads `.env` |
| `generate_clips.py` | submit all clips at once, wait, download |
| `check_actions.py` | gate: gestures, one application, unique show devices, opens needs open_state_ref, eye stability wording, `product_text.json` |
| `validate_concepts.py` | concept uniqueness vs the registry (set, light, palette, hook, bgm...), no kitchen, `skin_tone` |
| `product_text.py` | builds and checks the PRODUCT TEXT input |
| `hands_prompt.py` | arm/hand clause for every hands-only close-up prompt (which hand, which corner each forearm enters from); `python3 hands_prompt.py <hold> [right|left]` |
| `assemble_template.py` | per-run assembler template |
| `pipeline_preflight.py` | older preflight used by `omni.generate()` (see notes) |

## 5. Known notes and conflicts
- `pipeline_preflight.py` and `PIPELINE_INPUT_FORMAT.md` are an older system: they require `pipeline_products.json`, camera `locked_off` only and an on-camera opening. The current runs do not use them; clips go out through `generate_clips.py`, which has its own gate (`check_actions.py`). Camera: nearly locked off with at most a 10 percent push-in everywhere (omni.ZOOM_LIMIT, lock 4b, action files and the preflight all agree).
- Image checks are by eye: nothing automatic counts products or hands in an image, or checks the hand skin tone or the text.
- Omni sometimes returns 502 or drops the connection. A retry can double-charge because a job may already exist; the scripts retry at most once and log it.
- `concept_registry.json` is run history (rooms, palettes, BGMs used); delete entries only if you want those concepts reused.
